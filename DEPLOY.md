# Публикация сайта на Beget и перенос домена secretgarden62.ru с Tilda

Инструкция рассчитана на виртуальный хостинг Beget (тариф с поддержкой SSH и Docker-окружения — это все тарифы, кроме самых младших; при сомнениях уточните в поддержке). Домен secretgarden62.ru уже зарегистрирован в Beget, поэтому переключение занимает минуты, а не сутки.

Общий план:

1. Подготовить хостинг: сайт в панели, Node.js, общий доступ к `~/.local`.
2. Развернуть приложение и проверить его на техническом домене, **не трогая** рабочий сайт на Tilda.
3. Переключить домен secretgarden62.ru на Beget, выпустить SSL.
4. Настроить админку и переменные окружения.
5. Обновить данные в Яндексе и Google.

---

## 0. Что понадобится

- Логин и пароль от панели Beget (логин вида `u1234567` или буквенный — он же используется для SSH).
- SSH-клиент. В Windows подойдёт встроенный терминал PowerShell (`ssh` уже есть в Windows 10/11) или «Терминал» прямо в панели Beget (раздел **Сайты → иконка терминала**). Ниже все команды — для терминала на сервере.
- Доступ к репозиторию GitHub `andreymyskin/SecretGarden` (ветка `main` после слияния PR или ветка `cursor/secret-garden-site-1994`).

Требования приложения: Node.js **20.9 или новее** (Next.js 16 и sharp), запись в каталоги `data/` и `public/uploads/` — на виртуальном хостинге Beget диск постоянный, это подходит.

## 1. Подготовка хостинга

### 1.1. Создайте сайт в панели

1. Панель Beget → **Сайты** → **Добавить сайт**.
2. Имя каталога: `secretgarden62.ru` (так удобнее ориентироваться в файлах). Создастся папка `~/secretgarden62.ru/public_html`.
3. Пока **не прикрепляйте** к нему домен secretgarden62.ru — он ещё работает на Tilda. Вместо этого прикрепите технический поддомен для проверки: **Домены и поддомены → Добавить поддомен** к бесплатному домену вида `ваш_логин.beget.tech`, например `new.ваш_логин.beget.tech`, и в списке сайтов привяжите его к сайту `secretgarden62.ru`.

### 1.2. Включите SSH и зайдите на сервер

1. Главная панели → блок **SSH-доступ** → включить (если выключен).
2. Подключитесь:

```powershell
ssh ваш_логин@ваш_логин.beget.tech
```

3. Node.js на Beget работает только внутри Docker-окружения — перейдите в него (пароль тот же):

```bash
ssh localhost -p 222
```

В приглашении появится `(docker)`. Все дальнейшие команды выполняйте здесь.

### 1.3. Установите Node.js

Проверьте версию ОС сервера:

```bash
cat /etc/os-release | head -2
```

**Если Ubuntu 22.04** — ставим официальную LTS-сборку (пример — Node 22; допустима любая ≥ 20.9):

```bash
mkdir -p ~/.local && cd ~/.local
wget https://nodejs.org/download/release/v22.14.0/node-v22.14.0-linux-x64.tar.xz
tar xf node-v22.14.0-linux-x64.tar.xz --strip 1
rm node-v22.14.0-linux-x64.tar.xz
```

**Если Ubuntu 18.04** — официальные сборки ≥ 18 не запускаются; используйте сборку от Beget (список актуальных ссылок — в статье https://beget.com/ru/kb/how-to/web-apps/node-js, раздел «Установка Node.js версии 18.x и выше»). Нужна версия **20.x** (например 20.20.2):

```bash
mkdir -p ~/.local && cd ~/.local
wget "https://cp.beget.com/shared/bmcys1znnpqt7-csnFitRYB00n0Lnhrm/node-v20.20.2-bionic.tar.xz"
tar xf node-v20.20.2-bionic.tar.xz --strip 1
rm node-v20.20.2-bionic.tar.xz
```

Проверка (должно вывести версии, а не «command not found»):

```bash
node -v && npm -v && which node
```

Запомните путь из `which node` — обычно `/home/u/ваш_логин/.local/bin/node`.

### 1.4. Откройте общий доступ к `~/.local`

Сайты на Beget изолированы друг от друга, и веб-сервер не сможет запустить `node` из вашего домашнего каталога без этого шага.

1. Панель → **Файловый менеджер** → зайдите в корень аккаунта, включите показ скрытых файлов и откройте папку `.local`.
2. Меню **Инструменты → Настроить общий доступ к текущей директории**.
3. Выберите **Чтение и запись**, **Включая вложенные папки** → **Открыть доступ**.

## 2. Развёртывание приложения

### 2.1. Скачайте код

```bash
cd ~/secretgarden62.ru
git clone https://github.com/andreymyskin/SecretGarden.git app
cd app
```

Если публикуете не `main`, а рабочую ветку: `git clone -b cursor/secret-garden-site-1994 https://github.com/andreymyskin/SecretGarden.git app`.

### 2.2. Создайте `.env.local`

```bash
cat > .env.local <<'EOF'
ADMIN_PASSWORD=придумайте-стартовый-пароль
ADMIN_SECRET=длинная-случайная-строка-не-менее-32-символов
NEXT_PUBLIC_SITE_URL=https://secretgarden62.ru
YANDEX_VERIFICATION=
GOOGLE_SITE_VERIFICATION=
EOF
```

Случайную строку для `ADMIN_SECRET` можно получить командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Коды верификации заполните позже (шаг 5).

### 2.3. Установите зависимости и соберите проект

```bash
npm install --no-audit --no-fund
npm run build:hosting
```

`build:hosting` — это обычный `next build`, но с одним рабочим процессом и ограниченными пулами потоков (`NEXT_BUILD_CPUS=1`, `TOKIO_WORKER_THREADS=2`, `UV_THREADPOOL_SIZE=2`, лимит памяти 1,5 ГБ). На виртуальном хостинге действует лимит на число процессов и потоков на аккаунт, а обычный `npm run build` запускает по одному воркеру на каждое ядро сервера (на Beget их 24) и падает с ошибкой `OS can't spawn worker thread: Operation not permitted`.

Сборка занимает 1–3 минуты. Если процесс обрывается словом `Killed` (не хватило памяти на тарифе):

- попробуйте `NODE_OPTIONS=--max-old-space-size=1024 npm run build:hosting`;
- либо соберите проект на своём компьютере (`npm run build` в папке проекта на Windows) и загрузите папку `.next` (без подпапки `.next/cache`) по SFTP/в файловом менеджере в `~/secretgarden62.ru/app/.next`. Зависимости (`node_modules`) при этом должны быть установлены на сервере командой `npm install`.

### 2.4. Настройте запуск через Passenger

Node-приложения на виртуальном хостинге Beget запускает Apache `mod_passenger`. Точка входа уже есть в репозитории — `server.js`. Создайте `.htaccess` в каталоге **сайта** (не в `app/`), команды подставят правильные пути сами:

```bash
cd ~/secretgarden62.ru
cat > .htaccess <<EOF
PassengerNodejs $(which node)
PassengerAppRoot $(realpath app)
PassengerAppType node
PassengerStartupFile server.js
PassengerAppEnv production

RewriteEngine On
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^ https://%1%{REQUEST_URI} [R=301,L]
EOF
cat .htaccess
```

Готовый шаблон для сверки — `deploy/beget/htaccess.example`.

Статику (фотографии, логотип, загрузки из админки) отдаёт Nginx напрямую из `public_html`, поэтому заменяем его ссылкой на папку `public` приложения:

```bash
cd ~/secretgarden62.ru
rm -rf public_html
ln -s app/public public_html
```

Запустите приложение (Passenger перечитывает конфигурацию при появлении/обновлении `tmp/restart.txt` в каталоге приложения):

```bash
cd ~/secretgarden62.ru/app
mkdir -p tmp && touch tmp/restart.txt
```

### 2.5. Проверьте на техническом домене

Откройте `https://new.ваш_логин.beget.tech` (поддомен из шага 1.1). Проверьте:

- главная страница и фотографии открываются;
- `/admin` — вход по паролю из `.env.local`, загрузка тестового фото во вкладке «Шапка» и его удаление (проверяет запись в `public/uploads` и `data/`);
- `/oferta`, `/privacy`, `/robots.txt`, `/sitemap.xml`.

Если вместо сайта ошибка Passenger — смотрите лог ошибок сайта: панель → **Сайты → меню сайта → Логи** (файл ошибок Apache/Passenger). Типичные причины: не открыт общий доступ к `.local` (шаг 1.4), неверный путь в `PassengerNodejs`, не выполнена сборка (`.next` отсутствует).

## 3. Переключение домена с Tilda на Beget

Делайте это, когда сайт на техническом домене работает. Простой в переключении — единицы минут.

### 3.1. Прикрепите домен к сайту

1. Панель → **Домены и поддомены** → напротив `secretgarden62.ru` → **Прикрепить к сайту** → выберите сайт `secretgarden62.ru`.
2. Проверьте DNS: раздел **DNS** для домена. Для работы на хостинге Beget нужны NS-серверы Beget (`ns1.beget.com`, `ns2.beget.com`, `ns1.beget.pro`, `ns2.beget.pro`) и A-записи домена и `www`, указывающие на IP вашего хостинга. Если ранее для Tilda были прописаны A-записи на IP Tilda — Beget при прикреплении заменяет их на свои; убедитесь, что записей Tilda не осталось. MX-записи почты (если есть) не трогайте.
3. Если NS домена указывали не на Beget (реже) — переключите на NS Beget в разделе **Домены → Управление → NS-серверы**; обновление займёт до 24 часов.

### 3.2. Выпустите SSL-сертификат

1. Панель → **SSL** → выберите `secretgarden62.ru` → **Бесплатный сертификат Let's Encrypt** → установить (обычно 5–15 минут, для `www` тоже отметьте).
2. После выпуска в том же разделе включите **Перенаправление на HTTPS**.

### 3.3. Отключите домен в Tilda

В Tilda: **Настройки сайта → Домен** — удалите пользовательский домен `secretgarden62.ru`. Сам проект в Tilda пока не удаляйте (он может понадобиться, чтобы посмотреть старые тексты/адреса страниц). Через неделю-две, когда убедитесь, что всё работает, можно удалить.

### 3.4. Проверьте

- `https://secretgarden62.ru` открывает новый сайт, `http://` и `https://www.` перенаправляют на него.
- Откройте `https://secretgarden62.ru/robots.txt` — в конце должны быть строки `Host: https://secretgarden62.ru` и `Sitemap: https://secretgarden62.ru/sitemap.xml`.
- Кэш DNS на вашем компьютере может показывать старый сайт до часа: `ipconfig /flushdns` в PowerShell или проверьте с телефона через мобильный интернет.

## 4. Настройка после запуска

1. Зайдите в `https://secretgarden62.ru/admin` → вкладка **Безопасность**: смените стартовый пароль и **создайте код восстановления**, сохраните его в надёжном месте.
2. Проверьте вкладку **Разделы** — все нужные блоки опубликованы.
3. Резервные копии: панель Beget делает автоматические бэкапы файлов (раздел **Резервные копии**). Всё, что редактируется через админку, лежит в `~/secretgarden62.ru/app/data/` и `~/secretgarden62.ru/app/public/uploads/` — при переносе на другой сервер достаточно скопировать эти две папки.

### Как обновлять сайт после изменений в коде

```bash
ssh ваш_логин@ваш_логин.beget.tech
ssh localhost -p 222
cd ~/secretgarden62.ru/app
bash deploy/beget/update.sh
```

Скрипт сохраняет `data/content.json` с вашими правками, забирает новый код, пересобирает проект и перезапускает Passenger.

## 5. Поисковые системы: Яндекс и Google

Сайт уже отдаёт `title`/`description`, canonical, Open Graph, `robots.txt`, `sitemap.xml` и микроразметку `LocalBusiness`. Осталось «познакомить» с ним поисковики и сохранить позиции старого сайта.

### 5.1. Яндекс Вебмастер — https://webmaster.yandex.ru

1. Если secretgarden62.ru уже добавлен (от Tilda) — откройте его; иначе **Добавить сайт** → `https://secretgarden62.ru`.
2. **Подтверждение прав**: выберите способ «Мета-тег», скопируйте значение `content` (только код, без `<meta …>`), впишите в `.env.local` на сервере в `YANDEX_VERIFICATION=…`, затем `npm run build:hosting && touch tmp/restart.txt` (или `bash deploy/beget/update.sh`) и нажмите «Проверить». Способ «DNS-запись» тоже подойдёт: TXT-запись добавляется в панели Beget в разделе DNS домена.
3. **Индексирование → Файлы Sitemap** → добавьте `https://secretgarden62.ru/sitemap.xml`.
4. **Индексирование → Переобход страниц** → отправьте `https://secretgarden62.ru/`, `/oferta`, `/privacy`.
5. **Настройки индексирования → Региональность** → регион сайта «Рязань» (подтверждается по адресу на странице «Контакты»).
6. **Индексирование → Переезд сайта** — убедитесь, что главное зеркало `https://secretgarden62.ru` (без `www`, с HTTPS). Если Tilda-версия индексировалась как `www` — задайте переезд на версию без `www`.
7. Через 1–3 дня проверьте **Диагностика → Диагностика сайта** и **Индексирование → Страницы в поиске**: там будет видно, какие адреса старого сайта выпали. Если у сайта на Tilda были отдельные страницы (например `/price`, `/contacts`, `/oferta`-подобные), добавьте для них редиректы в `next.config.ts`:

```ts
const nextConfig: NextConfig = {
  async redirects() {
    return [
      { source: "/price", destination: "/#price", permanent: true },
      { source: "/contacts", destination: "/#contacts", permanent: true },
    ];
  },
};
```

8. **Яндекс Бизнес** (https://business.yandex.ru) — в карточке организации обновите ссылку на сайт (если она вела на Tilda-адрес) и проверьте фото/часы работы: карточка в Картах даёт заметную долю переходов для локального бизнеса. При желании подключите **Яндекс Метрику** (https://metrika.yandex.ru): создайте счётчик и передайте мне его номер — добавлю код на сайт (в политике конфиденциальности использование Метрики уже предусмотрено).

### 5.2. Google Search Console — https://search.google.com/search-console

1. **Добавить ресурс** → тип «Доменный ресурс» → `secretgarden62.ru`.
2. Подтверждение через **TXT-запись DNS**: скопируйте строку `google-site-verification=…`, в панели Beget → **DNS** домена → добавьте запись типа TXT для `@` с этим значением, подождите 5–30 минут → «Подтвердить». Альтернатива — «Ресурс с префиксом в URL» и мета-тег: код в `GOOGLE_SITE_VERIFICATION=…` в `.env.local`, пересборка, проверка.
3. **Файлы Sitemap** → `https://secretgarden62.ru/sitemap.xml`.
4. **Проверка URL** → введите `https://secretgarden62.ru/` → **Запросить индексирование**. Повторите для `/oferta` и `/privacy`.
5. Через несколько дней посмотрите **Страницы** (индексирование) и **Улучшения** — там же отобразится распознанная микроразметка.
6. **Google Бизнес-профиль** (https://business.google.com) — обновите ссылку на сайт и данные организации, если профиль есть.

### 5.3. Соцсети и агрегаторы

- Обновите ссылку на сайт в ВКонтакте, Telegram и WhatsApp Business, на YClients-странице записи.
- Если о студии есть записи на 2ГИС, Zoon, Яндекс Услугах и т.п. — проверьте, что ссылка ведёт на `https://secretgarden62.ru`.
- Ссылки на сайт в соцсетях показывают карточку с обложкой (`og-cover.jpg`); проверить внешний вид можно, вставив ссылку в диалог Telegram.

## Если хостинг не потянет сборку

Виртуальный хостинг ограничивает память процессов; если сборка стабильно падает даже с загрузкой готовой `.next` с компьютера, рациональный вариант — **облачный сервер (VPS) Beget** на Ubuntu 22.04 (самый младший тариф достаточен). Там сайт запускается штатно (`npm run build`, `npm run start` под `pm2`, Nginx как прокси с сертификатом Let's Encrypt), а домен переключается A-записью на IP сервера. Напишите — подготовлю отдельную инструкцию под VPS.
